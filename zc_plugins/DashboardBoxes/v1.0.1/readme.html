Dashboard Boxes

The Zen Cart 3.0.0 admin dashboard for Zen Cart 2.0 through 2.3: today's numbers, charts, recent orders with status badges, and panels you drag into place. No core file is changed.

What it does

Replaces the panels on the admin home page with the set Zen Cart 3.0.0 ships, laid out as a strip across the top, a wide main area and a sidebar:

+---------------------------------------------------------------+
|  Orders today  |  Revenue today  |  New customers  |  Reviews  |
+---------------------------------------+-----------------------+
|  Recent orders, with status badges    |  Orders by status     |
|  and quick filters                    |  Top sellers          |
|                                       |  Who's online         |
|  Sales, last 30 days (chart)          |  New customers        |
|                                       |  Sales and specials   |
|  Traffic history (chart)              |  Store snapshot       |
+---------------------------------------+-----------------------+

Drag any panel by its heading to another spot or another zone. The arrangement is saved as you drop it, for you alone; every admin keeps their own. A Reset layout link in the small toolbar above the panels puts the defaults back.

Why it exists

ZenExpert's Modern Dynamic Dashboard was merged into Zen Cart core in 2026 and ships with 3.0.0. For the 2.x releases it only exists as a package that overwrites thirty-one core admin files, and the 2.2 copy of that package replaces two files with their 2.1.0 versions, which kills every Configuration page on a 2.2 store.

This plugin is the same dashboard done as a plugin: it hooks the notifier the stock dashboard already fires, ships its own panels, stylesheet and script, keeps layouts in a table of its own, and touches nothing else. Installing it changes no file outside zc_plugins/; uninstalling it leaves nothing behind.

Installing

  1. Upload zc_plugins/DashboardBoxes/ so it lands at <store root>/zc_plugins/DashboardBoxes/v1.0.1/.
  2. In the admin, open Modules > Plugin Manager, select Dashboard Boxes and click Install.
  3. Open the admin home page.

The installer creates one table, dashboard_boxes_layout (with your table prefix, if any). It adds no configuration keys, registers no admin page and alters no core table.

The admin home page shows Zen Cart's own setup wizard until Store Name, Store Owner, Store Owner Email and Store Name and Address are all filled in under Configuration > My Store. The dashboard, plugin or not, appears only after that.

Coming from the replacement-file package

If your store already carries ZenExpert's Modern Admin Dashboard as replacement admin files, take those files out before or after installing this plugin. The plugin hides the stock panels but cannot undo what those files changed, and one of them, the old index.css, restyles this plugin's panels (the tell-tale is a status badge dropping below its row). In the paths below, admin/ means your renamed admin directory.

Files the package added: delete them

  • admin/ajax_dashboard.php
  • admin/includes/auto_loaders/config.modern_dashboard.php
  • admin/includes/init_includes/init_modern_dashboard_install.php (runs on every admin page load until it is gone)
  • admin/includes/css/index.css
  • admin/includes/javascript/index.js
  • admin/includes/modules/dashboard_widgets/MostPopularProductsDashboardWidget.php
  • includes/classes/ajax/zcAjaxAdminDashboardWidgetArrange.php (newer releases of the package only)

Core files the package replaced: put the stock ones back

Copy these from a fresh download of your Zen Cart version, not from another version. The package's own orders.php and general.php are 2.1.0 files, which is what breaks the Configuration pages on a 2.2 store.

  • admin/index_dashboard.php, admin/login.php, admin/orders.php, admin/orders_status.php, admin/password_forgotten.php
  • admin/includes/header.php, admin/includes/header_navigation.php
  • admin/includes/functions/admin_access.php, admin/includes/functions/general.php
  • admin/includes/css/login.css, menu.css, password_forgotten.css, stylesheet.css
  • admin/includes/languages/lang.english.php, english/lang.index.php, english/lang.orders_status.php
  • the eight stock files in admin/includes/modules/dashboard_widgets/: BaseStatistics, OrderStatus, RecentCustomers, RecentOrders, SalesReport, Specials, Traffic and WhosOnline

Releases of the package differ in which files they carry, so the sure way is to compare your admin directory against a stock copy of your version and restore whatever differs. The support thread can help if you are unsure.

Database

Nothing needs to be undone. The package may have added an orders_status_color_code column (which 2.2.1 and later have anyway and this plugin uses), a dashboard_layout column on the admin table, and a DASHBOARD_WIDGETS_CONFIG row in configuration. All three are harmless left alone; the configuration row can be deleted if you like, nothing reads it.

Arranging the panels

  • Move a panel: press on its heading and drag. Drop it anywhere in the top strip, the main area or the sidebar.
  • Saved as you go: each drop is stored the moment it lands. A small "Layout saved" confirmation shows in the toolbar; if the save fails, the toolbar says so in red.
  • Per admin: the layout belongs to the admin who made it. A colleague who logs in sees their own arrangement, or the default.
  • Reset layout: the link in the toolbar restores the default arrangement for you, after a confirmation.

Panels from other plugins that also use the stock dashboard notifier are shown where those plugins put them and are not draggable; only the panels this plugin knows about are.

Counts and charts are cached by Zen Cart's query cache for five to thirty minutes, as the stock panels are, so the dashboard stays quick on a busy store.

Order-status colors

Zen Cart 2.2.1 and later let you give each order status a color under Localization > Orders Status. The Recent Orders and Orders by Status panels show those colors as badges, and the quick-filter pills use them too. On Zen Cart 2.0 and 2.1, which have no color column, the panels fall back to Bootstrap's own badge colors: Pending amber, Processing blue, Delivered green, anything else gray.

Admin profiles

Each panel checks the same page permission the stock panel did. An admin whose profile has no access to Orders sees no Recent Orders, Orders by Status or Sales panel, and the Today at a Glance strip drops the cards they may not see. A panel that is not shown is simply not rendered; it keeps its place in the saved layout.

Customizing

The Recent Orders panel honors the same site-specific overrides the stock one does, in admin/includes/extra_datafiles/site_specific_admin_overrides.php:

$recentOrdersMaxRows = 20;                    // rows (default 10)
$recentOrdersWidgetOrderStatusIDs = [1, 2, 5]; // quick-filter pills
$show_status_pills = false;                   // hide the pills
$includeAttributesInPopoverRows = false;      // no attribute lines in the popover

Everything the plugin draws sits inside .dbx-widget, each panel wrapper carrying data-dbx-widget="<Name>". Put your own rules in admin/includes/css/site-specific-styles.php, which core loads after every stylesheet, rather than editing the plugin's index.css.

Another plugin can add a panel of its own through NOTIFY_DASHBOARD_BOXES_REGISTRY, or replace the layout about to be rendered through NOTIFY_DASHBOARD_BOXES_LAYOUT. Both are documented in the package's docs/CUSTOMIZING.md.

How it works

  • The stock dashboard builds a list of widgets and fires NOTIFY_ADMIN_DASHBOARD_WIDGETS with it. The plugin's observer marks the nine stock widgets invisible and adds its own ten, pointing at files inside the plugin directory, in the zones and order you last saved.
  • The 2.x dashboard renders three equal columns. The plugin's stylesheet makes the first one full width and the other two a two-to-one pair, which is the top strip, the main area and the sidebar. Nothing is moved by script, so the page does not jump on load.
  • Core loads a plugin's index.css, index.php and index.js on the dashboard page by name, so the stylesheet, the chart library and the drag-and-drop script arrive without any header hook and load nowhere else.
  • A drop posts the arrangement to admin/ajax.php?act=dashboardBoxes&method=save, a class in the plugin's own AJAX directory that core's front controller finds. It requires an admin session and the session's security token, accepts only registered panel names in known zones, and stores the result in the plugin's table.
  • Every box carries a width, full, two thirds or one third of the page, stored with the layout. Free renders it (two one-third boxes dropped together into the main area sit side by side) but has no control to set it; that is what a layout controller adds.
  • Chart.js 4.5.1 is bundled and served from the plugin directory. jQuery UI and Bootstrap 3 are already on every admin page; nothing is loaded twice and nothing comes from a CDN.

Upgrading the plugin

Upload the new version directory beside the old one, open Plugin Manager and click Upgrade. Saved layouts are kept. Delete the old version directory once Plugin Manager shows the new one.

Uninstalling

Plugin Manager > Dashboard Boxes > Uninstall. The layout table is dropped and the stock dashboard is back at once. Delete zc_plugins/DashboardBoxes/ afterwards if you want the files gone as well.

Troubleshooting

  • The dashboard looks stock. Plugin Manager must show the plugin as installed and enabled, not merely present. If the home page is Zen Cart's setup wizard, finish it (see Installing). On Zen Cart 3.0.0 the dashboard you see is core's own, by design.
  • After an upgrade the dashboard looks like the old version. Zen Cart's shipped zc_plugins/.htaccess tells browsers to keep stylesheets and scripts for an hour, so a browser can hold the previous version's files for that long. A hard refresh (Ctrl+F5, or Cmd+Shift+R on a Mac) fetches the new ones.
  • The panels are there but in three equal columns and will not drag. The browser did not load the plugin's stylesheet or script. Check that zc_plugins/DashboardBoxes/v1.0.1/admin/includes/css/index.css is reachable in a browser; the shipped zc_plugins/.htaccess allows .css and .js, but a stricter server rule can block them.
  • "The layout could not be saved." The AJAX call was refused. The usual cause is a session that has timed out; reload the page. If it persists, look in logs/ for a myDEBUG-adm- file from the moment of the drop.
  • The charts are empty. Sales needs orders in the last 30 days; Traffic needs rows in the store's counter history, which builds up one per day once the counter runs.
  • Today's numbers look wrong at the start of the day. "Today" is measured on your server's PHP clock, set by Configuration > My Store > Time Zone on 2.x. If the database server runs in a different time zone the orders list may still say "yesterday" for a while; the dashboard follows PHP.

Compatibility

Zen Cartv2.0.0, v2.0.1, v2.1.0, v2.2.0, v2.2.1, v2.2.2, v2.2.3 and the v2.3 branch. Installs on v3.0.0 and stands aside, because that release's own dashboard is this design.
PHP8.0 through 8.5, from a single codebase, with no deprecation notices at E_ALL.
Not supportedv1.5.8 and earlier: their dashboard has no notifier to hook.
DatabaseOne table of its own, dashboard_boxes_layout. No configuration keys, no change to any core table.
AssetsOne stylesheet, one script and Chart.js, all served from the plugin directory. No CDN, no external services.
